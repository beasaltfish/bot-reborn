KWS spike

Throwaway verification code. It is not on web/'s product path — but it stays in the repo, because this page has already been reopened twice. It answers one question from spec item ⑤: can this phone carry a resident sherpa-onnx KWS? Four numbers come out — download size, per-frame cost against frame length, battery drain over 30 minutes, and whether it is still running after 30 minutes with the screen off.

Keywords

One per line: a token sequence plus @label, optionally :boost and #threshold — that per-keyword threshold is exactly the asymmetry spec §5.5 asks for. This model uses ARPAbet phonemes plus toned pinyin, not BPE, and a wrong token aborts the wasm module outright, so the box is validated against tokens.txt here before Start is pressed.

Keep-alive sound (the second approach)

Android does not let a background app hold the microphone — which is why, about 60 seconds after the screen goes off, the audio clock and the fed counter stop together. A tab that is playing audio, however, makes Chrome hold a media session, which keeps the tab foreground enough to keep the mic. Two playback paths run at once here: an <audio> loop (Chrome hangs its media notification on that one, and it does not get suspended along with the capture AudioContext) and an oscillator attached to the capture context itself. 60 Hz at −40 dBFS sits far above Chrome's silence threshold (about −60 dBFS, so the tab counts as audible) and far below what a phone speaker can reproduce (they roll off hard below 300 Hz) — inaudible in the room, and nothing meaningful reaches the mic. Leaving the box unchecked is the control run, behaving exactly like the run before this feature existed.

The buttons below only make sound. They do not start the microphone, do not load the model, and are unrelated to the checkbox above. By design the current setting should be inaudible at a normal distance — put your ear to the speaker. Press “−20 dBFS” first to confirm the speaker is working at all, then come back and listen to the real setting.

Audition—

To find out whether the hiss is the amplifier: set the level to -58 (just over the system's ≈ −60 dBFS silence threshold) and listen again. If the hiss is unchanged, it has nothing to do with what we play — the amplifier hisses the moment it powers up, and no waveform will remove it.
At 18 kHz only the <audio> half sounds. The capture context runs at 16 kHz, so by Nyquist it can represent at most 8 kHz, and an 18 kHz oscillator would alias down into a 2 kHz squeal. That option skips the oscillator, and the log says so.
