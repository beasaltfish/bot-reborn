每行一条：token 序列 + @标签，可选 :boost 与 #阈值（逐词阈值，正是规格 §5.5 要的那个不对称）。这个模型用 ARPAbet 音素 + 带调拼音，不是 BPE——写错的 token 会让 wasm 直接 abort， 所以点「开始」前先在本地对 tokens.txt 校验一遍。

保活音（路二实验）

安卓不准后台应用用麦克风——这就是每次息屏约 60 秒后音频钟和已喂一起停掉的 原因。而正在播放声音的标签页会让 Chrome 挂住一个媒体会话，从而仍算前台， 麦克风也就保得住。这里同时上两种播放：一个 <audio> 循环 （Chrome 的媒体通知挂在它身上，且不随采集用的 AudioContext 一起被挂起）和一个 挂在采集 context 上的振荡器。60 Hz、−40 dBFS：远高于 Chrome 判静音的门槛 （约 −60 dBFS，所以标签页算「有声」），又远低于手机喇叭能发出的频段 （300 Hz 以下基本发不出来），所以屋里听不见，麦克风也收不到。 不勾选就是对照组，行为和你刚测的那轮完全一致。

下面几个按钮只放声音，不启动麦克风、不加载模型，也和上面那个勾选框无关。 按设计，当前设置在正常距离下就该听不见——要贴着耳朵听。先点「−20 dBFS」 确认喇叭确实在出声，再回来听当前设置。

试听状态—

验沙沙声是不是功放的锅：把音量填 -58（刚好高过系统判静音的 约 −60 dBFS 门槛）再听。要是沙沙一点没变，那就跟我们放什么无关，是功放一通电 自己在响，换任何波形都去不掉。
18 kHz 那档只有 <audio> 一半在响：采集用的 context 跑在 16 kHz，按采样定理它最高只能表示 8 kHz，18 kHz 的振荡器会折回成 2 kHz 的啸叫—— 所以那一档会跳过振荡器，日志里会说明。
